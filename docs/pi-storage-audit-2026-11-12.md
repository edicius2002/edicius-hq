The first `du -xhd1 /` showed about 16 GiB because the SSH user could not read private state. A second read-only run with `sudo -n` showed about 21 GiB, consistent with `df`. A root dry run of the new pruner on `bodas` identified the same 19 eligible releases and held the two releases with additional ignored files.

## One-time cleanup applied

After the owner authorized the operation, the pinned retention script ran on `bodas` under an exclusive deployment lock. It removed the 19 verified old checkouts and held the two with additional ignored files. The active release `fb41d038` and prior rollback release `fb4f572` remained present; the checked collector services and retention timer remained active. Six releases remain, using 2.3 GiB. `df -B1 /` changed from **21,953,376,256 bytes used / 37,772,677,120 available** to **14,475,276,288 used / 45,250,777,088 available**. This whole-filesystem delta also reflects any concurrent activity, so the preflight candidate sum of **7,008,193,007 bytes** is the more specific estimate of release data removed.

## Default retention prepared in the repository

`ops/pi/prune_releases.py` is called at the end of `ops/pi/deploy-release.sh`, after a **new** release and its services have been verified. A deployment lock prevents two deployments from overlapping, and the pruner rechecks the active release before each deletion. It keeps the four newest releases, the active release, and the preceding rollback release. A repeat of the already active commit does not prune because that invocation cannot identify the earlier rollback release reliably.

Only direct, SHA-named Git checkouts under `/opt/edicius-hq/releases` are eligible. Their Git state must be clean, and their only ignored content may be `services/api/.venv/`. Unexpected entries, mounts, and modified checkouts are retained for inspection. A pruning failure does not roll back an otherwise healthy deployment. Manual invocation without `--apply` is a preview.

The one-time cleanup used the tested local script over SSH. The automatic deployment hook was subsequently deployed and verified on `bodas` at commit `ae74c86d66a71b8fb38cc18ce9868790a78d4cb2`; it removed one more verified old release while retaining two unverified releases and the preceding rollback release.

## Data to retain

Do not automatically prune `/var/lib/edicius-hq`: it holds the authoritative Airfare archive, cursors, queues, and browser profiles. Do not remove backups, Finance documents, X data, or SEACE records without a dataset-specific retention rule and a tested restore. Any future local PostgreSQL data and WAL should live on an SSD, with backups outside the Pi.
